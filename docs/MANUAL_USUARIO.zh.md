# GestorPro 用户手册

本手册介绍 GestorPro 目前在生产环境（`https://app.gestorpro.us`）中的实际运作方式。它是为企业主、主管和店内人员编写的，无需任何技术知识。

**如何阅读本手册**

- 以**粗体**显示的文字，就是您在屏幕上看到的原文（按钮名称、字段名称、提示信息）。
- 在屏幕上，必填字段的名称旁边带有星号（*）；在本手册中记为**名称**（必填）。
- **B/.** 表示巴波亚（balboa），即巴拿马的货币；与美元 1 比 1 等值。
- 每项任务开头都会说明哪些**角色**可以执行（**管理员**、**主管**、**员工**）。
- 在手机上，表格可以左右滑动：操作按钮（**更正**、**付款**、**编辑**……）位于**行末**；向右滑动即可看到。

## 1. 欢迎

### 1.1 什么是 GestorPro

GestorPro 是您企业的管理应用。通过它，您可以管理：

- **财务**：支出、供应商、采购发票、供应商付款、应付账款、每个班次的收银结账、利润看板和现金流。
- **考勤**：每位员工的档案、在打卡机（平板）上的上下班打卡、工时记录、加班时长和加班预支。
- **审计**：每次有人更正或作废资金记录时，都会留下永久记录。

每家公司都有自己独立的空间：您的数据绝不会与其他公司的数据混在一起。

### 1.2 GestorPro 不是什么

- **它不是收银系统（POS）。** 它不会逐件登记销售商品，也不会打印小票。这些由 Firestec（您的收银系统）完成。GestorPro 只记录每个班次的**日结**（收银结账），填入 Firestec 报告的总额。
- **它不管理库存。** 没有商品、库存数量或价格。
- **它不是工资系统。** 它不计算也不发放工资。它只记录加班时长余额，并允许预支其中一部分。
- **它不是您的银行。** 现金流显示的是您登记过的收支记录，而不是您银行账户的实际余额。

### 1.3 如何登录及使用要求

1. 打开浏览器，输入 **https://app.gestorpro.us**。
2. 输入您的邮箱和密码，然后点击**登录**。

如果您输入 `gestorpro.us` 而没有前面的 `app.`，页面将无法打开。这是正常的：请始终使用完整地址。

使用要求：

- 电脑、平板或手机上的现代浏览器（Chrome、Edge、Safari 或 Firefox）。
- 网络连接。**没有网络，应用无法使用**；不提供离线模式。
- 员工打卡建议每个门店配备一台专用平板（见 2.6）。
- Android 应用正在准备中（是同一网页的封装版本）。目前尚未向客户发布；请使用浏览器（见 7）。

### 1.4 语言

界面提供**Español**、**English** 和**中文**三种语言。您可以在登录页面（表单上方的下拉框）或侧边菜单（仅宽屏显示；手机上看不到）切换语言。该下拉框没有标签：直接显示 **Español** / **English** / **中文**。切换立即生效，并且会在该浏览器中记住您的选择。

只有界面会被翻译：您自己输入的名称（类别、供应商、员工）以及服务器的错误信息始终以西班牙语显示。

### 1.5 角色

每个账号拥有三种角色之一：**管理员**（拥有全部权限）、**主管**（操作和更正资金记录，管理员工和供应商，审核打卡并审批预支；不能管理用户、门店和打卡机，也看不到二维码和 PIN）和**员工**（仅可查看，另可申请加班预支）。完整的权限矩阵见附录 A。

请记住：看到某个按钮或链接并不代表您能使用它；服务器会在每次操作时核对权限。如果您尝试执行超出自己角色的操作，会看到 **No tiene permiso para esta operación.**（您没有权限执行此操作）。

> **关于员工角色的重要提醒。** **员工**角色的账号"仅可查看"，但可以查看**全部财务信息**：看板、支出、付款、供应商、欠款以及所有人的工时。对收银员来说，这并不是一个无害的角色。收银员通常**不需要账号**：她们用自己的员工编号在打卡机上打卡即可。请只为确实需要查看这些信息的人创建员工角色的账号。

### 1.6 全系统通用的规则

> **在 GestorPro 中，任何东西都不会被删除。** 类别、供应商、员工、门店、打卡机和用户账号只会被**停用**，绝不会被删除；其历史数据会保留。资金记录（支出、付款、发票、收银结账）和打卡记录是**不可修改的**：既不能编辑，也不能删除。错误的支出、付款或结账只能**更正一次**，方式是先做一笔*冲正*（系统自动生成的一条记录，用于抵消原记录），如有需要，再做一笔金额正确的*更正*。所有这些都会记录在**财务审计**中。详见 6.1。

> **现付与赊购。** **现付**发票已经付清，不产生欠款：它不会出现在应付账款、应付账龄、付款计划器或对账单中；可在**全部发票**中查看。**赊购**发票会产生欠款，并出现在所有欠款相关的页面中。详见 3.4。

### 1.7 找到方向：菜单和页面地图

## 2. 开始使用（初始配置）

如果您的公司是新建的，请按以下顺序进行。每一步都指向对应的章节。

| 步骤 | 做什么 | 谁 | 章节 |
|---|---|---|---|
| 1 | 用临时密码登录并修改密码 | 管理员 | 2.1 |
| 2 | 创建**门店**（店面） | 管理员 | 2.2 |
| 3 | 检查**支出类别**（默认自带四个） | 管理员 / 主管 | 2.3 |
| 4 | 登记常用的**供应商** | 管理员 / 主管 | 2.4 |
| 5 | 新增**员工**，设置其操作角色（**Cajera**（收银员）、**Verificador**（核验员））和 PIN | 管理员 / 主管 | 2.5 |
| 6 | 为每个店面登记一台**打卡机**，并用令牌配置平板 | 管理员 | 2.6 |
| 7 | 创建主管的**用户账户**，并强烈建议创建**第二位管理员** | 管理员 | 2.7 |

> **建议：**请始终保持**两名有效的管理员**。如果唯一的管理员忘记密码或被停用，恢复访问需要联系服务商支持（6.6）。

### 2.1 首次登录：强制修改密码

角色：全部。

管理员交给您的密码是**临时的**。首次登录时，应用不会让您看到任何页面，直到您把它换成自己的密码。

1. 打开 **https://app.gestorpro.us**。您会看到带有 **GP** 标志的卡片、标题 **GestorPro** 和副标题**企业管理**。如需要，可在表单上方的下拉框中选择语言。
2. 输入您的**邮箱**和**密码**，然后点击**登录**（或按 Enter 键）。登录过程中按钮显示**登录中…**。
3. 随后会全屏显示**修改密码**对话框，并提示**你的密码是临时的，必须修改后才能继续。**
4. 在**当前密码**中输入您收到的临时密码。
5. 输入您的**新密码**（**至少 8 个字符。**），并在**确认新密码**中再输入一次。
6. 点击**修改密码**。
7. 您会看到**密码已更新**以及文字 **Por seguridad cerramos todas tus sesiones. Vuelve a iniciar sesión con tu nueva contraseña.**（为了安全，我们已关闭您的所有会话。请用新密码重新登录）。点击**前往登录**，并用新密码登录。

**完成后您会看到：**首页（见 1.7）。如果您登录前打开的是某个具体链接，应用会直接带您到该链接。

**常见错误（登录时）：**

| 提示信息 | 含义与处理方式 |
|---|---|
| **邮箱为必填项。** / **密码为必填项。** | 您有字段留空。 |
| **Credenciales inválidas.**（凭据无效） | 邮箱或密码错误，**或**您的账户已被停用，**或**您的公司已被暂停。这个提示是故意做成一样的。如果您确定密码无误，请联系管理员。 |
| **Rate limit exceeded, retry in 1 minute**（英文，意为"请求过多，请 1 分钟后重试"） | 一分钟内从您的网络连接发起了超过 10 次登录尝试（无论成功或失败）。请等待一分钟后再试。 |
| **登录失败，请重试。** | 连接失败。请检查您的网络。 |

**常见错误（修改密码时）：**

- **请输入当前密码。** — 第一个字段留空了。
- **新密码至少需要 8 个字符。**
- **新密码必须与当前密码不同。**
- **两次输入的密码不一致。** — 确认密码与新密码不一样。
- **Credenciales inválidas.**（凭据无效） — 您输入的临时密码不正确。请再次向管理员索取。
- **尝试次数过多，请稍后再试。**

**请注意：**

- 此对话框没有取消或关闭按钮。如果您没完成修改就关闭浏览器，临时密码仍然有效，对话框会再次出现。
- 没有"忘记密码"功能，也不能自行注册。因此表单底部写着：**仅限授权人员。如需访问请联系管理员。**完整流程详见 6.5。
- 邮箱开头或结尾的空格会被忽略。密码则按原样处理。

### 2.2 门店

角色：仅管理员（主管和员工能看到列表和按钮，但点击后会收到 **No tiene permiso para esta operación.**（您没有权限执行此操作））。

门店是指每个店面或分店。员工、打卡机、支出和发票都归属于某个门店。

1. 菜单**管理 → 门店**。
2. 点击 **+ 新增门店**。会打开**新增门店**。
3. 输入**名称**（必填）。
4. 选择**异常模式**：**PIN**（默认）、**主管**或 **PIN 或主管**。它决定当常规验证失败时，打卡机会向员工要求什么：员工的 PIN、主管用邮箱和密码授权，或两者任选其一。
5. 点击**创建门店**。

**编辑**（**保存更改**）和**停用** / **启用**的用法与员工（2.5）相同。停用的门店会从下拉框中消失，但其数据会保留。

**请注意：**如果选择**主管**，该门店无法使用 PIN（**Esta sede no permite excepción por PIN.**（该门店不允许 PIN 例外））；如果选择 **PIN**，主管将无法授权（**Esta sede no permite excepción por supervisor.**（该门店不允许主管例外））。对于没有主管在场的店面，请使用 **PIN** 或 **PIN 或主管**。

### 2.3 支出类别

角色：管理员、主管。

类别是用来给支出分类的列表。每家公司有自己的类别目录；创建公司时自带四个：**Servicios públicos**（水电等公共服务）、**Alquiler**（租金）、**Mantenimiento**（维护）和 **Pago a empleado**（员工支付；此类别已标记为员工支付类别）。

**创建类别：**

1. 菜单**管理 → 支出类别**。
2. 点击**新建类别**。
3. 输入**名称**（字段示例："如:广告、燃油……"）。
4. 如果该类别的支出需要注明支付给了哪位员工（半月工资、预支、结算），请勾选**员工支付类别**。
5. 点击**创建类别**。

**编辑：**点击该行的**编辑**，修改名称和/或员工支付勾选框，然后点击**保存更改**。（勾选框旁的屏幕提示写着**创建后不可更改。**，但系统在编辑时确实接受更改；该提示已过时。）

**停用：**点击**停用**。该类别在登记支出时不再出现，但旧的支出仍会显示它。要恢复，请勾选**显示已停用**并点击**重新启用**。

**常见错误：**

- **Ya existe una categoría activa con ese nombre en esta empresa.**（本公司已存在同名的有效类别） — 请换一个名称或重新启用已有的。如果名称与某个已停用的类别相同，系统会将其重新启用并提示**类别已重新启用。**
- **Ya existe una categoría con ese nombre en esta empresa.**（本公司已存在同名类别） — 编辑或重新启用时，名称与另一个类别冲突。
- **Debe quedar al menos una categoría de "pago a empleado" activa: la necesita el cobro de horas extra. Crea o activa otra antes de desactivar esta.**（至少要保留一个有效的"员工支付"类别：加班预支需要它。停用此类别前请先创建或启用另一个） — 加班预支会在该类别下生成支出（4.12）。
- **No hay cambios que aplicar.**（没有需要保存的更改） — 您没做任何修改就保存了。

### 2.4 供应商

角色：管理员、主管。（员工能看到列表和按钮，但点击后会收到 **No tiene permiso para esta operación.**（您没有权限执行此操作）。）

**登记：**

1. 菜单**管理 → 供应商**。
2. 点击 **+ 新增供应商**。
3. 输入**名称**（必填）。可选填**税号**（RUC 或 NIT：供应商的税务登记号）、**电话**和**联系人**。
4. 点击**创建供应商**。

**完成后您会看到：**供应商出现在表格中，包含**名称**、**税号 / 证件**、**电话**、**联系人**、**欠款总额**和**状态**（**启用** / **停用**）。**欠款总额**是其赊购发票尚未付清的金额；大于零时会高亮显示。

**编辑 / 停用：** **编辑** → 修改数据 → **保存更改**（如果清空某个可选字段，该字段会被删除）。**停用**：该供应商在登记新发票时不再出现，但其发票、付款和对账单都会保留；**启用**可恢复。

**请注意：**

- 系统不会阻止登记两个同名供应商：创建新供应商前请先查看列表。
- 您也可以在发票表单中用 **+ 新增**按钮直接创建供应商（3.4）。

### 2.5 员工（档案、操作角色、PIN 与二维码）

**用户与员工的区别。**这是两个不同的概念：

- **用户**是拥有邮箱和密码、**登录 GestorPro** 的账户（在**用户**中管理，2.7）。
- **员工**是用工号或 PIN **在打卡机打卡**的工作人员档案（在**员工**中管理）。员工打卡**不需要账户**。

档案中的**操作角色**（**Cajera**（收银员）、**Verificador**（核验员）；随公司一起创建）描述的是店内职能，不授予系统权限。正是这些角色使员工在登记日结时出现在下拉框中（3.2）。

**新增员工。**角色：管理员、主管。

1. 菜单**主要功能 → 员工**。
2. 点击 **+ 新增员工**。会打开**新增员工**。
3. 输入**工号**（必填；字段示例："例如 E001"；公司内唯一）。这是员工打卡时使用的号码。
4. 输入**姓名**（必填）。
5. 选择**门店**（必填）。
6. 输入**固定薪资 (B/.)**（必填；B/. 是巴波亚，巴拿马的货币）：这是**月**薪；用于计算加班费（4.9）。
7. 输入 **PIN（4 位）**（必填）。提示：**避免连续数字（1234）和重复数字（0000）。**
8. **参考照片**字段是禁用状态，显示**人脸识别 — 待定**：目前不上传照片。
9. 勾选适用的**操作角色**（**Cajera**（收银员）、**Verificador**（核验员））。
10. 点击**创建员工**。

**完成后您会看到：**员工出现在表格中（**工号**、**姓名**、**门店**、**角色**、**薪资**、**状态**）。如果您是管理员且列表刷新成功，会自动打开该员工的二维码以便打印；如果刷新失败，您会看到**员工创建成功。刷新列表后会显示该行；二维码在其「QR」按钮中。**

**常见错误：**

- **Ya existe un empleado con ese número.**（已存在该工号的员工）
- **工号、姓名和门店为必填项。**
- **薪资必须为大于或等于零的数字。**
- **PIN 必须为 4 位数字。**
- **El PIN es demasiado predecible: evita repeticiones (0000) y secuencias (1234, 4321).**（PIN 太容易猜到：请避免重复数字（0000）和连续数字（1234、4321））

**编辑、停用或重新启用。**角色：管理员、主管。**编辑**：字段相同，但没有 PIN（例如可用于修改姓名或门店）；点击**保存更改**。**停用**：一键完成，无需确认。已停用的员工**无法打卡**（**Empleado no encontrado o inactivo.**（未找到员工或员工已停用）），并从日结和预支的下拉框中消失；其历史记录会保留。**启用**可恢复。

**查看、打印或重新生成二维码。**角色：仅管理员。

1. 点击行末的 **QR**。会打开 **{nombre} 的二维码**，显示图像及下方的代码文本。
2. **打印**会打开一个新窗口，包含姓名、二维码和代码，并启动打印（请允许弹出窗口）。
3. **重新生成二维码**会创建一个新代码。提示：**重新生成会立即使旧二维码失效。**

**重要：**目前打卡机**仅通过工号**识别员工（例如 `E001`）。打印出的二维码可作为员工的身份卡，但在打卡机上用扫描器扫码**目前还不能用**（打卡机会把它当作工号处理，并回应 **Empleado no encontrado o inactivo.**（未找到员工或员工已停用））。二维码扫描功能留待未来版本。

**重置 PIN。**角色：仅管理员。

1. 点击行末的**重置 PIN**。会打开**重置 PIN — {nombre}**。
2. 输入**新 PIN（4 位）**并点击**保存 PIN**。对话框关闭且没有提示：PIN 已经更改。

当前的 PIN 无法查看，只能替换。

### 2.6 打卡机与平板配置

角色：仅管理员。

打卡机是员工用来打卡的共用平板或电脑。每台打卡机归属于一个门店，并拥有一个**令牌**（一串长的秘密密钥），用于授权该设备发送打卡记录。

**步骤 A — 登记打卡机：**

1. 菜单**管理 → 打卡机**。
2. 点击 **+ 新增打卡机**，输入**名称**（必填），选择**门店**（必填），然后点击**创建打卡机**。
3. 会出现卡片**打卡机「{nombre}」的令牌**，并提示**请复制并在设备（打卡机界面）中配置。出于安全考虑，仅显示一次。**请立即复制令牌，然后点击**关闭**。

**步骤 B — 配置平板：**

1. 在平板上打开 **https://app.gestorpro.us/kiosco**。无需登录。
2. 在红色面板**设备未配置**中粘贴令牌，然后点击**保存**。
3. 面板变为绿色的**设备已授权**。平板已准备就绪。

**请注意：**

- 令牌保存在平板的浏览器中。如果浏览器数据被清除（或更换浏览器、更换平板），令牌会丢失，需要重新配置。
- 如果令牌丢失，请在打卡机列表中点击**重新生成令牌**（另一次重新生成正在进行时该按钮会被锁定），然后重新配置平板；旧令牌会立即失效。在打卡机上，**重新配置**按钮会打开**重新配置设备令牌**界面，其中有**保存**和**取消**。
- 应用中无法编辑、停用或删除打卡机。
- 没有有效令牌时，任何打卡都会返回 **Kiosco no autorizado.**（打卡机未授权）。

### 2.7 用户（访问账户）

角色：仅管理员。

**创建账户：**

1. 菜单**管理 → 用户**。副标题：**访问账户：新增与重置密码**。
2. 点击 **+ 新增用户**。会打开**新增用户**。
3. 输入**姓名**、**邮箱**和**临时密码**（三项均为必填；**至少 8 个字符。用户首次登录时必须修改。**）。
4. 选择**角色**（必填）：**管理员**、**主管**或**员工**（默认为员工）。创建员工角色的账户前，请先阅读 1.5 的提示。
5. 点击**创建用户**。

**完成后您会看到：**卡片**用户已创建**，提示**请将临时密码告知该用户：首次登录时必须修改。**以及按钮**再创建一个用户**。在表格中（列为**姓名**、**邮箱**、**角色**、**状态**、**密码**、**创建时间**、**操作**），**密码**列会显示**临时密码待修改**，直到该用户修改密码为止。

**常见错误：**

- **姓名、邮箱和密码为必填项。** / **邮箱格式不正确。** / **临时密码至少需要 8 个字符。**
- **El email ya está en uso.**（该邮箱已被使用） — 该邮箱已在 GestorPro 中拥有账户（在任何公司）。请换一个邮箱，或请服务商支持为该账户开通您公司的访问权限。

**请注意：**在点击**创建用户**之前请记下临时密码：它不会再次显示。请当面交给对方，切勿写在显眼的地方。

**更改角色：**在该行的**角色**列，从下拉框中选择新角色。立即保存，无需确认。您自己的那一行无法更改（**你不能更改自己的角色。**）：请让另一位管理员操作。

**重置他人密码：**见 6.5。

**停用或重新启用：**点击**停用**（红色）或**重新启用**。立即生效。停用会关闭其所有会话，系统将拒绝其登录（该用户会看到 **Credenciales inválidas.**（凭据无效））。重新启用不会更改密码。您不能停用自己的账户。

账户不能删除，也不能修改姓名或邮箱：如果有人离开公司，请将其停用。不要让公司没有任何有效的管理员。如果某个用户属于多家公司，您会看到 **La cuenta pertenece a más de una empresa: su contraseña se gestiona desde la plataforma.**（该账户属于多家公司：其密码由平台管理）或 **…su estado se gestiona desde la plataforma.**（…其状态由平台管理）：这些操作由服务商支持处理。

## 3. 每日操作

**每日流程（可打印）：**

- **开门时：** 打开平板，确认显示 **设备已授权** 且已选择 **打卡机**；每位员工打 **上班** 卡。
- **营业期间：** 每笔支出当场登记（3.3）；收到的发票及时登记（3.4）；**向供应商付款当天就登记付款**（3.5），因为付款记录的日期总是当天。
- **每班结束时：** 收银员清点钱箱；核验员在看板中登记结账（3.2），并与 Firestec 核对。
- **一天结束时：** 主管检查 **审核队列**（3.6）和预支功能中 **待处理** 的申请（4.12）。

### 3.1 员工打卡（平板上的分步操作）

角色：任何在职员工；无需账户。本节适合打印后贴在平板旁边。

该页面标题为 **GestorPro — 打卡机**，并有自己的语言选择器。（如果这台平板上有已登录的会话，点击 **GP** 标志会返回应用。）

**如何打上班、就餐或下班卡：**

1. 在 **欢迎** 页面（"请选择打卡机和打卡类型以开始。"），打开页面后第一次使用时，选择这台平板的 **打卡机**（选择器初始显示 **— 请选择打卡机 —**，选定后对后续员工保持不变，直到页面刷新）。点选 **打卡类型**：**上班**、**外出就餐**、**就餐返回** 或 **下班**。点 **继续**。
2. 在 **身份识别** 页面（"请输入工号或刷您的二维码卡。"），输入您的 **工号**（例如 `E001`），然后点 **继续** 或按 Enter。目前只能用工号；二维码卡暂时还不能读取（见 2.5）。
3. 在 **人脸验证** 页面，您会看到 **模拟模式 — 无真实摄像头** 和 **验证结果：**，有三个选项：**匹配 — 人脸通过**（默认选中）、**不匹配 — 人脸被拒** 和 **无活体 — 活体检测失败**。目前平板没有启用摄像头：**保持默认选项不变**，然后点 **登记打卡**。另外两个选项用于模拟验证失败，只用于测试或强制走例外打卡。
4. 如果结果为失败，会出现 **验证失败**，并提示 **此打卡将被标记给主管审核。** 接下来需要输入的内容取决于门店的异常模式（2.2）：
   - **PIN** 模式：输入您的 **员工个人 PIN：**。
   - **主管** 模式：由一位主管输入其 **主管邮箱：** 和 **主管密码：**。
   - **PIN 或主管** 模式：会显示 **个人 PIN**（字段 **您的个人 PIN：**）和 **主管** 两个选项卡。
   点 **确认打卡**。**取消** 会返回验证页面。
5. 在最后一个页面，您会看到 **打卡已登记** 和 **{tipo}打卡登记成功。** 5 秒后（**{n} 秒后切换下一位员工…**）自动返回首页，也可以点 **下一位员工**。

页面上可能出现标记 **例外打卡 — 待审核**（主管将进行审核）或 **HR 提醒：核对参考照片**（七天内三次或以上例外打卡）。

**一天的正确顺序：** **上班** → **外出就餐** → **就餐返回** → **下班**。工时在打 **下班** 卡时计算。

**打卡机常见错误：**

| 提示信息 | 处理方法 |
|---|---|
| **Empleado no encontrado o inactivo.**（未找到员工或员工已停用） | 工号有误或该员工已被停用。请输入工号（不是二维码的编码）。 |
| **PIN incorrecto.**（PIN 不正确） | 请重试。如果忘记了，管理员可在 **员工 → 重置 PIN** 中重置。 |
| **Esta sede no permite excepción por PIN.**（本门店不允许 PIN 例外） / **Esta sede no permite excepción por supervisor.**（本门店不允许主管例外） | 该门店配置了其他异常模式（2.2）。 |
| **Autorización de supervisor inválida.**（主管授权无效） | 该邮箱/密码不属于本公司在职的主管或管理员（或其临时密码尚未修改）。 |
| **凭据无效，请重试。** | PIN 或授权被拒绝时的通用提示。请重试。 |
| **Kiosco no autorizado.**（打卡机未授权） | 平板没有有效令牌，或在选择器中选了与本平板令牌不对应的打卡机（选择器也会显示其他公司的打卡机）。请选择正确的打卡机或通知管理员。 |
| **Kiosco no encontrado o inactivo.**（未找到打卡机或已停用） | 所选打卡机已不存在或已停用。 |
| **网络错误，请重试。** | 请检查平板的网络连接（见 6.4）。 |

**负责人请注意：** 只要人脸验证还是模拟的，员工只要知道别人的工号就可以替别人打卡；只有在验证失败时，例外 PIN 才能阻止。如果您担心这一点，请让服务商启用 **revisión total**（全量审核：所有打卡都进入审核队列，3.6）。

如果员工打卡打错了，见 6.3。

### 3.2 登记班次现金结账（每日销售）

角色：管理员、主管。

GestorPro 不逐笔登记销售。每个班次结束时，每位收银员登记 **一次现金结账**：按盘点（清点钱箱里的钱）记录现金、刷卡、Yappy 和彩票各有多少，总额必须与 Firestec 报告的数字一致。这个结账就是为看板提供数据的"每日销售"。

规则：**每位收银员在同一门店、同一天、同一班次只能结账一次**。如果登记错了，就对该结账进行更正（只能更正一次，6.1）；不要再登记一次。

**盘点术语：**

- **Yappy**：通过手机转账（Banco General）收到的款项。
- **彩票**：用钱箱里的钱支付给顾客的彩票奖金。中奖彩票留在钱箱里代替现金，并 **计入结账总额**（因此页面上会提示 **彩票是放在钱箱里已付出的奖金。**）；这样盘点才能与 Firestec 报告的销售额一致。

**开始之前：** 负责结账的员工必须具有操作角色 **Cajera**（收银员），负责核验的员工必须具有操作角色 **Verificador**（核验员），均在 **员工** 中分配（2.5）。否则他们不会出现在下拉列表中。

**关于班次和结账人（推荐做法）：** 如果一家门店全天只有一位收银员，请始终使用 **早班**（班次只是用来区分同一天多次结账的标签）。**结账人** 是清点并核验钱箱的人；最好与收银员不是同一个人（内部控制），不过系统也允许是同一人。

1. 菜单 **主要功能 → 看板**。
2. 点 **+ 登记当日结账**。会打开 **登记现金结账**，并有提示 **按 Firestec 输入结账时的现金盘点。总额必须与 Firestec 报告的总额一致。**
3. 选择 **门店**（必填）。
4. 选择 **班次**（必填）：**早班**、**午班** 或 **夜班**。
5. 选择 **收银员**（必填；格式为 `E001 - 姓名`；先列出本门店的，再列出其他门店的，后者带后缀"（其他门店）"）。
6. 检查 **结账日期**（必填）。
7. 选择 **结账人**（必填；即核验员）。如果您的公司没有任何具有 Verificador 角色的员工，会预先选中 **当前用户：{您的姓名}**。
8. 可选：**开班时间** 和 **结账时间**。
9. 在 **现金盘点** 中输入 **现金 (B/.)**、**刷卡 (B/.)**、**Yappy (B/.)** 和 **彩票 (B/.)**（B/. 指巴波亚，巴拿马的货币单位）。下方会实时计算 **结账总额**。
10. 将 **结账总额** 与 Firestec 的总额比对，然后点 **登记结账**（按 Enter 不会提交；必须点按钮）。

**完成后您会看到：** 提示 **{fecha} 的结账已登记，金额 B/. {total}。**（带 ✓ 标记；6 秒后自动隐藏，或点 ✕ 关闭），新的一行在 **本期销售结账** 中高亮显示，看板的卡片重新计算。

**示例：** 早班，收银员 E003 - Ana。现金 320.00、刷卡 150.50、Yappy 80.00、彩票 12.00 → **结账总额** B/. 562.50。如果 Firestec 报告 B/. 562.50，即可登记。

**如果盘点与 Firestec 不一致：**

1. 重新清点现金，检查刷卡和 Yappy 的凭证以及彩票。
2. 登记 **真实** 的盘点数（钱箱里实际有的钱），而不是 Firestec 的数字：结账必须反映实际存在的钱。
3. 表单 **没有备注字段**。请在 GestorPro 之外记录差额（现金记录本、给老板留言）。如果短缺被认定为损失，可以用专门创建的类别（例如"Faltante de caja"，即现金短缺）把它登记为一笔支出，并在 **描述** 中写明差额。

**常见错误：**

- **请选择结账班次。**
- **请至少输入一项现金盘点金额。**
- **现金金额必须为大于或等于零的数字。**（刷卡、Yappy、彩票同理）。
- **Ya existe el cierre de esa cajera y turno para la fecha; use una corrección para ajustarlo.**（该收银员该班次当天的结账已存在；请用更正来调整）— 该结账已登记。请从列表中更正（6.1）；不要再次登记。
- **没有具备“收银员”角色的员工。请在“员工”中分配。** — 请在员工资料中分配该操作角色。
- 警告（不阻止提交）：**收银员与核验员为同一人（{nombre}）。允许，但请检查内部控制。**

**请注意：** 收银员和核验员以固定文本保存（"E001 - 姓名"）；如果以后修改了员工姓名，旧的结账记录不会改变。

**查看本期结账。** 角色：所有人。在看板中，卡片下方是 **本期销售结账** 列表，包含 **日期**、**门店**、**班次**、**收银员**、**结账人**、**总额 / 盘点**（含按方式的明细）和 **状态**（**有效** / **已更正** / **已作废**）。使用上方的筛选条件（**起始**、**截止**、**门店**、**班次**、**收银员**）。

### 3.3 支出

支出是指 **不属于** 供应商发票付款的任何资金流出：电费、水费、房租、燃油、广告、给员工的付款（半月工资、预支薪资、结算）等。供应商付款在 **应付账款** 中登记（3.5），不在这里。已登记的支出不能编辑或删除；只能更正（6.1）。

**登记一笔支出。** 角色：管理员、主管。

1. 菜单 **主要功能 → 支出**。
2. 点 **+ 登记支出**。会打开 **登记支出** 卡片。
3. 选择 **类别**（必填；只显示启用的类别）。如果需要的类别不存在，使用下拉框下方的链接 **+ 新建类别**：在输入框中填写名称（示例："如:广告、燃油……"），如适用则勾选 **员工支付**，然后点 **创建类别**。新类别会自动选中。
4. 选择 **门店**（必填）。
5. 输入 **金额 (B/.)**（必填；例如 `45.50`）。
6. 检查 **业务日期**（必填；默认为今天，可以修改：允许登记以前日期的支出）。
7. 可选：**描述（可选）**，例如"七月电费单"。
8. 如果类别属于 **员工支付**，会出现 **员工信息** 区块：输入 **员工 ID**（必填；字段示例："员工 UUID 或标识"），并选择 **支付类型**（**未指定**、**半月**、**每月**、**每周**、**预支**、**结算**、**其他**）。
9. 点 **登记支出**。

**完成后您会看到：** 提示 **支出登记成功。**，表单关闭，该支出出现在列表中。列表底部显示 **本期合计（N 笔）：** 及总和。

**关于员工 ID 字段（使用员工支付类别前请先阅读）：**

- 该字段要求输入员工的技术标识（一长串字母和数字），**不是** "E001" 这样的短工号，而且不是下拉列表。
- 该标识 **不会在 GestorPro 的任何页面上显示**。请向服务商的技术团队索取，并与每位员工对应保存在一份清单中。
- 系统 **不会验证** 该标识是否对应真实员工：输入错误会原样保存，支出列表的 **员工** 列会显示原始文本，而不是"E001 - 姓名"。
- 在拿到标识之前的实用替代方案：加班预支请使用 **预支**（4.12），它会自动创建支出；半月工资或结算请使用 **未** 标记为员工支付的类别（例如"Planilla"，即工资单），并在 **描述** 中写明员工姓名。

**常见错误：**

- **金额必须为正数。** / **El monto del gasto debe ser mayor que cero.**（支出金额必须大于零）
- **La categoría de gasto indicada está inactiva.**（所选支出类别已停用）— 请在 **支出类别** 中重新启用该类别，或选择其他类别。
- **La categoría es de pago a empleado: el empleadoId es obligatorio.**（该类别为员工支付：员工 ID 为必填）— 缺少员工标识。
- **无法加载数据，请刷新页面。** — 门店或类别加载失败；请刷新。

**请注意：** 在 **预支** 中标记为已支付的加班预支会自动创建对应的支出（4.12）；不要再手工登记一次。

**查询某个期间的支出。** 角色：所有人。

1. 菜单 **主要功能 → 支出**。
2. 调整 **起始** 和 **截止**（默认从本月 1 日到今天）。列表会自动刷新；**筛选** 按钮会重新查询。

列表显示 **类别**、**描述**、**金额**、**日期**、**员工**（工号和姓名，无法解析时显示标识）、**支付类型** 和 **状态**（**有效**、**已更正** 或 **已作废**）。如果某笔支出已更正，原金额会以删除线显示在现行金额旁边。已作废的支出在合计中按零计算。如果某笔支出"找不到"，请先检查筛选的日期；如果列表为空，您会看到 **所选期间没有支出记录。**

**更正一笔支出：** 点该行末尾的 **更正**，然后按 6.1 操作。

### 3.4 登记采购发票（现付或赊购）

角色：管理员、主管。

**现付与赊购：最容易混淆的区别。** 登记发票时必须指明 **采购类型**：

| | **赊购（应付账款）** | **现付（当场付清）** |
|---|---|---|
| 是否产生欠款？ | 是。会留下未付余额。 | 否。收到时已付清。 |
| 是否需要到期日？ | 是，必填。 | 否。 |
| 是否出现在应付账款、账龄、付款计划器和对账单中？ | 是。 | **否。** 这些页面只显示欠款。 |
| 是否可以登记付款？ | 是，直到付清。 | 否。如果尝试：**Una compra de contado se paga en el acto y no admite abonos.**（现付采购当场付清，不接受付款登记） |
| 之后在哪里可以看到？ | 在所有欠款页面和 **全部发票** 中。 | **只在全部发票中**（状态为 **已付**），以及作为金额计入看板。 |
| 是否计入看板？ | 计入 **采购登记**（按发票日期）；只有付款后才计入 **供应商付款**。 | 在发票当天同时计入 **采购登记** 和 **供应商付款**。 |
| 是否出现在现金流中？ | 每笔付款作为流出。 | 否（没有登记的付款）。 |

**示例：** 您购买了 B/. 500 的配件并当场付款。请登记为 **现付**。您不会在 **应付账款** 中看到它（不欠款），但会在 **全部发票** 中看到，状态为 **已付**，并且会从看板的 **利润** 中扣除。如果供应商给您 30 天账期，则登记为 **赊购** 并填写到期日：它会出现在 **应付账款** 中，余额 B/. 500，直到您付款。

**步骤：**

1. 菜单 **主要功能 → 应付账款**。
2. 点 **+ 登记发票**。会打开 **登记发票** 卡片。
3. 选择 **供应商**（必填；显示为"名称 — RUC"；只列出启用的供应商）。如果不存在，点 **+ 新增**，填写 **名称**（必填）和可选信息，然后点 **创建供应商**：新供应商会自动选中。
4. 选择 **门店**（必填）。
5. 输入 **发票号**（必填），与供应商单据上的一致（字段示例："例如 F-2024-001"）。
6. 输入 **总额 (B/.)**（必填）。
7. 选择 **采购类型**（必填）：**赊购（应付账款）**（默认）或 **现付（当场付清）**。
8. 填写 **开票日期**（必填；默认为空）。
9. 如果是赊购，填写 **到期日**（必填；选择现付时该字段会消失）。
10. 点 **登记发票**。

**完成后您会看到：** **发票登记成功。** 如果是赊购，它会出现在 **应付账款** 列表中，状态为 **待付**。**如果是现付，它不会出现在这个列表中**：请在 **全部发票** 中查找（4.2）。

**常见错误：**

- **总额必须为正数。**
- **赊购需要填写到期日。**
- **Ya existe la factura "F-001" para ese proveedor; use una corrección para ajustarla.**（该供应商已存在发票 "F-001"；请用更正来调整）— 每个发票号在同一供应商下唯一。请检查是否之前已登记过。
- **El proveedor o la sede indicados no existen.**（所选供应商或门店不存在）— 该供应商或门店已被停用；请刷新。

**请注意：** 发票登记后 **不能编辑或删除**，也不能从现付改为赊购，或更正其金额。点按钮前请核对发票号、金额和类型。如果已经登记错了，见 6.2。

### 3.5 登记给供应商的付款（部分或全额）

角色：管理员、主管。

**规则：不允许超额付款。** GestorPro **绝不允许支付超过发票欠款的金额**，无论是登记付款还是更正付款。如果您尝试向余额为 B/. 100 的发票付款 B/. 150，会看到 **金额不能超过余额（B/. 100.00）。** 或来自服务器的 **El pago (150.00) excede el saldo pendiente (100.00).**（付款 150.00 超过未付余额 100.00）。这可以防止输入错误和重复付款。

1. 菜单 **主要功能 → 应付账款**。
2. 找到该发票（必要时使用 **按状态筛选：**），点该行末尾的 **付款**。只有发票状态不是 **已付** 时才有这个按钮。
3. 会打开 **登记付款** 对话框，显示 **供应商：**、**发票：**、**发票总额：**、**已付：** 和 **未付余额：**。
4. 输入 **付款金额 (B/.)**（必填）。可以小于余额（部分付款）或等于余额（全额付款）。
5. 点 **登记付款**。

**完成后您会看到：** 对话框关闭，列表更新：**已付** 增加，**余额** 减少，状态变为 **部分付款**（还有余额时）或 **已付**（余额为零时）。

**部分付款示例：** 发票 F-2024-001，金额 B/. 800，9 月 30 日到期。

| 操作 | 已付 | 余额 | 状态 |
|---|---|---|---|
| 登记发票 | 0.00 | 800.00 | 待付 |
| 付款 B/. 300 | 300.00 | 500.00 | 部分付款 |
| 付款 B/. 500 | 800.00 | 0.00 | 已付 |
| 尝试再付款 B/. 50 | — | — | 不允许：没有 **付款** 按钮 |

**常见错误：**

- **请输入大于零的有效金额。**
- **金额不能超过余额（B/. X）。**
- **Una compra de contado se paga en el acto y no admite abonos.**（现付采购当场付清，不接受付款登记）

**请注意：** 从页面登记时，付款日期总是 **今天**（没有日期字段）。**请在付款当天登记付款。** 付款不能编辑或删除：只能从 **付款历史** 中更正（4.3 和 6.1）。

### 3.6 打卡审核队列

角色：管理员、主管。

用于让负责人确认或拒绝 **例外打卡**（因验证失败而通过 PIN 或主管授权完成的打卡）。如果服务商在服务器上启用了 **revisión total**（全量审核；这是整个安装的全局配置，不是按公司设置），则 **所有** 打卡都会进入队列。

1. 菜单 **主要功能 → 审核队列**。您会看到 **{n} 条待处理**、**刷新** 按钮，以及每条打卡一张卡片，显示员工、类型（**上班**、**外出就餐**、**就餐返回**、**下班**）、**打卡机：**、日期和时间，以及验证方式（**PIN 例外** / **主管例外**）。
2. 要接受，点 **通过**：卡片立即消失。
3. 要拒绝，点 **拒绝**。会打开 **拒绝打卡**，显示 **员工：{nombre} — {fecha} 的{tipo}**；可选填写 **拒绝原因（可选）：**，然后点 **确认拒绝**。

**完成后您会看到：** 卡片从队列中移除；如果没有剩余，显示 **没有待审核的例外打卡。**

**重要：** 拒绝 **不会删除打卡，也不会重新计算工时**；只是记录您的决定。如果被拒绝的打卡是虚假的（例如有人替别人打卡），还需要到 **工时** 中更正当天的小时数和加班金额（4.10）。

**错误：** **Este fichaje ya fue revisado.**（此打卡已被审核）（另一位负责人已先审核）、**验证打卡失败。**、**拒绝打卡失败。**

## 4. 每周与每半月

**每周 / 每半月例行工作：**

- **每周：** 查看 **应付账款**（4.1）和 **应付账龄**（4.4）；用本周预算在 **付款计划器** 中制定方案（4.5）；按决定付款（3.5）。
- **每半月：** 查看 **工时**（4.8）并更正异常（4.10）；计算应付的加班费（4.11）；处理 **预支** 申请（4.12）；把半月工资登记为支出（3.3）。
- **每月：** 为每个需要核账的供应商生成 **对账单**（4.6）；查看 **看板**（5.1）并导出会计需要的资料（FAQ 12）。

### 4.1 应付账款：查看欠谁、欠多少

角色：全部（只有管理员和主管能看到 **+ 登记发票**、**付款** 和 **规划付款**）。

1. 菜单 **主要功能 → 应付账款**。
2. 使用 **按状态筛选：** 下的按钮 **全部状态**、**待付**、**逾期**、**部分付款**、**已付**。

列：**供应商**、**发票**、**总额**、**已付**、**余额**、**到期日**、**状态**。没有结果时显示：**暂无应付账款。** 或 **没有状态为“{estado}”的应付账款。**

**状态如何判定**（按此顺序）：

1. **已付**：余额已为零。
2. **部分付款**：已有付款（即使已逾期）。
3. **逾期**：没有任何付款且到期日已过。
4. **待付**：其余情况。

一张已有部分付款且已逾期的发票显示为 **部分付款**，而不是 **逾期**。此处只显示赊购发票（见 3.4）。页头链接：**查看账龄**、**规划付款**、**全部发票**。

### 4.2 全部发票（现付和赊购）

角色：全部。只读。

1. 菜单 **主要功能 → 全部发票**（或应付账款中的 **全部发票** 链接）。
2. 按 **供应商**、**类型**（**全部类型**、**现付（当场付清）**、**赊购（应付账款）**）和 **状态**（**全部状态**、**待付**、**逾期**、**部分付款**、**已付**）筛选。更改后列表会自动重新加载。

表格显示 **供应商**、**发票**、**类型**、**总额**、**已付**、**余额**、**到期日**（现付显示 —）和 **状态**。现付发票的 **已付** 总是等于总额，**余额** 为 0，状态为 **已付**。在这里不能付款，也不能更正任何内容。

### 4.3 付款历史

角色：全部（**更正** 仅限管理员和主管）。

1. 菜单 **主要功能 → 付款历史**。页头有 **对账单** 链接（4.6）。
2. 按 **供应商**、**起始**、**截止** 和 **状态**（**有效**、**已更正**、**已作废**）筛选。**清除筛选** 会清空全部条件。

上方显示当前筛选结果的汇总：**付款笔数**（数量）、**登记总额**、**现行总额** 和 **已更正/作废**。表格显示 **日期**、**供应商**、**发票**、**登记人**、**登记金额**、**现行金额** 和 **状态**，每页 20 条（**上一页** / **下一页**）。

**更正一笔付款：** 点击该行末尾的 **更正**（仅当状态为 **有效** 时可用），然后按 6.1 操作。

### 4.4 应付账龄：安排付款优先级

角色：全部。只读。

1. 菜单 **主要功能 → 应付账龄**（或从应付账款点击 **查看账龄**）。页面标题为 **应付账款账龄**。
2. 按 **供应商**、**账龄**（区间）、**排序**（**余额最大**、**账龄最老**、**供应商（A–Z）**、**采购日期**）和 **搜索**（供应商或发票号；按 Enter 或离开输入框时生效）筛选。**清除筛选** 会清空全部条件。

**“账龄”是什么意思：** 页面上有提示：**账龄按采购日期起的自然日计算，不代表合同逾期：系统不要求填写到期日。这是未付余额的账龄。** 也就是说，它计算的是从发票的 **开票日期** 到今天的天数，**不是** 超过到期日的拖欠天数（“逾期”）。一张发票可以在应付账款中显示为 **逾期**，同时在这里处于 **0–30 天** 区间。

**您会看到：**

- 卡片 **未付总额**、**未付采购数**、**供应商数**、**最老账龄**（以天计）和 **最大欠款供应商**。
- **账龄分布** 条，分为 **0–30 天**、**31–60 天**、**61–90 天** 和 **90 天以上** 四个区间。点击某个区间即可按其筛选。
- **按供应商欠款** 表，显示各区间的欠款，并有 **对账单**、**付款历史** 和 **登记付款** 的快捷入口。
- **有余额的采购** 表，包含 **原金额**、**有效付款**、**待付余额**、**账龄**（最老的带 **+90天** 标记）和 **区间**。

**操作：** **创建付款计划**（把当前筛选带到付款计划器）、**打印 / 保存 PDF** 和 **导出 CSV**（导出全部筛选结果；可用 Excel 打开）。**刷新** 链接会重新计算。

### 4.5 付款计划器：用一笔预算制定付款方案

角色：管理员、主管。

它用来回答：“这周我有 B/. X（B/. 是巴拿马货币巴波亚），该付哪些发票、每张付多少？”

**非常重要：** 付款计划器给出的是一份 **建议**。页面上写明：**这是一份付款建议：不登记任何付款、不修改欠款。用于决策并打印给财务人员手工执行。** 它不保存任何内容：离开页面后计划即丢失。要执行计划，您必须逐笔手动登记付款（3.5）。

1. 菜单 **主要功能 → 付款计划器**（或从应付账款点击 **规划付款**，或从账龄页点击 **创建付款计划**）。页面标题为 **供应商付款计划器**，并有 **返回账龄** 链接。
2. 在 **1. 配置计划** 中，输入 **可用预算 (B/.)**。
3. 选择 **策略**：**最旧优先**（默认）、**小额优先** 或 **按供应商比例**。
4. 可选：**供应商**、**最低付款（可选）**、**每供应商上限（可选）**、**截止日期（可选）** 以及账龄区间按钮（可同时选多个）。
5. 点击 **生成计划**。
6. 查看 **预算使用** 条、**计划前后账龄** 表和 **按供应商计划**。
7. 在 **2. 明细与调整** 中，可以手动修改每张发票的 **计划付款**（**余额** 按钮会填入全部余额）。如果改乱了，可用 **全部清空** 或 **恢复建议**，然后点击 **应用金额** 让系统重新校验。**用满全部预算** 会把预算调整为欠款总额。
8. 在 **3. 确认报告** 中查看汇总，并用 **打印 / 保存 PDF** 或 **导出 CSV** 带走。

**完成后您会看到：** 报告底部带有免责说明 **本计划为付款建议，尚未登记为真实付款。执行时请在应付账款中逐笔登记付款。**

**常见错误：**

- **请输入大于零的有效预算。**
- **配置已更改：下方是上一次的计划。请点击「生成计划」刷新。**
- **计划总额超过可用预算。** / **某笔付款超过其发票余额。** — 请调整被标记的金额。
- **当前筛选下没有未付发票。**

### 4.6 供应商对账单

这是与供应商核账用的文件：期初欠多少、本期新增了哪些发票、付了多少、还剩多少。

1. 菜单 **主要功能 → 供应商对账单**（页面有 **查看账龄** 链接）。
2. 选择 **供应商**（必填；没有“全部供应商”的对账单）。
3. 填写 **起始** 和 **截止**。
4. 点击 **生成对账单**。

**您会看到：** 您的公司名称、**期间：**、**生成日期：**、供应商信息，以及卡片 **期初余额**、**本期采购**、**有效付款**、**更正 / 作废** 和 **期末余额**。下方是表格，包含 **日期**、**单据**、**摘要**、**借方**（增加欠款：“Factura de compra a crédito”，即赊购发票）、**贷方**（减少欠款：“Pago a proveedor”，即供应商付款）和逐行累计的 **余额**。已更正或已作废的付款会连同原因一起标注。

- 现付采购不会出现（它们不产生欠款）。
- 如果生成后又更改了供应商或日期，会看到 **筛选条件已更改：下方显示的仍是上一次的对账单。请点击「生成对账单」刷新。**

### 4.7 完整示例：从发票到向供应商付款

> 8 月 1 日，“Repuestos del Istmo”送来一批滤清器，发票 F-3310，金额 B/. 900，30 天账期。
>
> 1. **登记发票（3.4）：** 应付账款 → **+ 登记发票** → 供应商“Repuestos del Istmo” → 门店 → 发票号 `F-3310` → 金额 `900` → **赊购（应付账款）** → 开票日期 01/08 → 到期日 31/08 → **登记发票**。显示为 **待付**，余额 900。
> 2. **第 3 周，业务员来收款，您付了 B/. 300（3.5）：** 在 F-3310 那一行点击 **付款** → 金额 `300` → **登记付款**。状态 **部分付款**，余额 600。请在付款当天登记。
> 3. **月底，与业务员核账（4.6）：** 对账单 → 供应商“Repuestos del Istmo” → 起始 01/08 → 截止 31/08 → **生成对账单** → **打印 / 保存 PDF**。您会看到借方 900、贷方 300、期末余额 600。
> 4. **决定下一次付款（4.5）：** 付款计划器 → 本周预算 → **生成计划** → 打印。之后在应付账款中登记实际付款。

### 4.8 工时：查询工作时数和加班时数

角色：全部（员工只能查询：**更正** 按钮对所有人显示，但员工点击后服务器会返回 **No tiene permiso para esta operación.**（您没有权限执行此操作）；**清扫孤立打卡** 仅限管理员）。

1. 菜单 **主要功能 → 工时**（副标题 **查询与更正工时**）。
2. 调整 **起始** / **截止** 并点击 **筛选**（或 **刷新**）。用 **搜索员工** 按工号或姓名筛选。

**限制：“每个人几点到的？”** GestorPro 目前没有逐条列出打卡及其时间的页面：工时页只显示当天的总时数，审核队列只显示例外打卡（含时间）。如果您需要准确的上班时间，请向供应商的技术支持索取；没有打卡记录的工时（手工记录）也无法从页面创建。

### 4.9 工时如何计算

系统在打 **下班** 卡时自动计算工时，规则如下：

1. **已工作** =（下班 − 上班）− 用餐休息（就餐返回 − 外出就餐）。如果没有用餐打卡，则不扣除休息时间（除非该员工被分配了带默认休息的班次，目前无法从页面设置）。**已工作** 包含加班时数。
2. **分类** 按夜间时段（18:00 至 06:00）判定：完全不在该时段为 **白班**，全部在该时段为 **夜班**，部分在该时段为 **混合**。
3. **法定工时**：白班 8 小时，夜班 7 小时，混合 7,5 小时。超出部分为 **加班**。
4. **固定法定加成**：白班 25 %，夜班 50 %，混合 75 %，**节假日 150 %**。这些是 **巴拿马《劳动法》规定的最低标准**：在应用的任何地方都 **不能配置、不能下调**。
5. **上限**：每天最多支付 3 小时加班，每周最多 9 小时。超出部分会显示在 **加班** 列，但在主管审核并更正之前不予支付。
6. **小时工资** = 月薪 ÷ 240。
7. **加班金额** = 可支付加班时数 × 小时工资 ×（1 + 加成），四舍五入到分。该金额 **计入员工的加班余额**（4.11、4.12）。

注：上限（3 小时 / 9 小时）和除数 240 是系统的标准，**尚待法律确认**；加成比例已经确认。节假日由技术团队维护，没有录入页面。

**示例（按表格格式）：** Ana 的月薪为 B/. 600 → 小时工资 = 600 ÷ 240 = **B/. 2.50**。某天她打卡：上班 08:00、外出就餐 12:00、就餐返回 13:00、下班 19:00。

- 在场 11 小时，休息 1 小时 → **已工作 10h 0m**。
- 有 1 小时（18:00–19:00）落在夜间时段 → **混合**，法定工时 7,5 小时。
- **加班 2h 30m**（在 3 小时上限内）。
- 混合加成 75 % → 2,5 × 2.50 × 1,75 = **加班金额 B/. 10.94**。
- 如果那天是节假日：2,5 × 2.50 × 2,50 = **B/. 15.63**。

**快速计算表**（用于手动更正工时，见 4.10）：

| 月薪 | 小时工资（÷ 240） | 2 小时白班加班（×1,25） | 2 小时夜班（×1,50） | 2 小时混合（×1,75） | 2 小时节假日（×2,50） |
|---|---|---|---|---|---|
| B/. 600 | 2.50 | 6.25 | 7.50 | 8.75 | 12.50 |
| B/. 800 | 3.33 | 8.33 | 10.00 | 11.67 | 16.67 |
| B/. 1 000 | 4.17 | 10.42 | 12.50 | 14.58 | 20.83 |

公式：**加班时数 ×（月薪 ÷ 240）× 系数**，系数为 1,25 / 1,50 / 1,75 / 2,50。系统在最后一步才四舍五入，因此可能有 1 分钱的差异。

### 4.10 更正一条工时

角色：管理员、主管。

1. 在该行末尾点击 **更正**。会打开 **更正工时**，显示 **员工：{nombre} ({número}) — 日期：{fecha}**。
2. 填写 **更正原因**（必填）。
3. 只填写想要修改的项：**工作分钟数**（以分钟计：8 小时 30 分 = 510）、**加班分钟数**、**加班金额 (B/.)**。留空的项不会改变（输入框会以提示形式显示当前值）。
4. 如果该工时有异常，请保持勾选 **解决异常（标记为已更正）**。
5. 点击 **保存更正**。

**完成后您会看到：** 该工时状态变为 **已更正**。如果修改了 **加班金额**，员工的加班余额会按差额调整。

**重要：** 三个字段相互独立。**修改分钟数不会重新计算金额。** 如果更正了时数，请同时用 4.9 的表格算出加班金额并填入。每次更正都会永久记录（原值、新值、原因和操作人）。

### 4.11 本半月我欠每位员工多少加班费

角色：管理员、主管（员工可查询）。

GestorPro 不做半月工资结算：您在应用之外支付。要知道金额：

1. **工时** → 填写本半月的 **起始** / **截止** → **搜索员工** → 把该员工各条工时的 **加班金额** 列加总（或导出/记下）。
2. 减去该期间已在 **预支** 中支付的预支款（状态 **已支付**）。
3. 把半月工资的支付登记为支出（3.3），使用员工支付类别，**支付类型：半月**（或使用不带员工标记的“Planilla”（工资单）类别，见 3.3）。

**重要限制：** **预支** 页面显示的 **累计余额** 是历史上所有加班金额减去已批准预支后的总和；在系统外支付半月工资后 **不会归零**，也没有页面可以扣减它（预支最多只允许 80 %）。请只用预支页面的余额来决定预支，用 **本期工时** 来计算半月工资。

### 4.12 预支：加班费预支

**预支** 页面（标题 **加班预支**）**不是工资单，也不是发工资**，与向客户收款毫无关系。每条含加班的工时都会把钱累加到员工的 **加班余额** 中。通过这个页面可以在发半月工资之前 **预支** 一部分余额；主管批准后，管理员在应用之外交付现金，再把它标记为已支付。

规则：

- 最多只能预支余额的 **80 %**，再减去已申请且待处理的金额。
- 如果金额 **小于或等于审批阈值**（B/. 100），申请一创建就是 **已批准**，并立即扣减余额。如果超过阈值，则创建为 **待处理**，批准时才扣减。
- 80 % 和 B/. 100 是您公司的默认值；**没有页面可以修改**：只有供应商的技术团队可以调整。
- 余额永远不会为负。拒绝不影响余额。
- 点击 **标记已支付** 时，系统会自动创建一笔 **支出**：使用第一个启用的员工支付类别、该员工的门店、当天日期，以及 **支付类型**“cobro de horas extra”（加班预支，这个值不在支出的下拉列表中）。请不要再手动登记一次。

**申请预支。** 角色：全部。

1. 菜单 **主要功能 → 预支**。
2. 在 **新申请** 中选择 **员工**。您会看到 **累计余额：B/. X**、**可取百分比：80%** 和 **可预支：B/. Y**。
3. 填写 **申请金额 (B/.)**（最多为可预支金额）。
4. 点击 **申请预支**。

**完成后您会看到：** **申请已成功提交。**，并且该申请出现在 **预支申请** 列表中，状态为 **已批准** 或 **待处理**。

**示例：** Ana 的余额为 B/. 60。可预支 = 80 % = **B/. 48**。她申请 B/. 30 → 因为 30 ≤ 100，立即变为 **已批准**，余额降到 B/. 30。管理员交给她 B/. 30 现金并点击 **标记已支付** → 状态 **已支付**，并在 **支出** 中出现一笔 B/. 30 的支出。

**常见错误：**

- **请输入大于零的有效金额。**
- **El monto solicitado (B/. 50.00) excede tu monto adelantable disponible (B/. 40.00; 80% del saldo, menos lo ya solicitado).**（申请金额 B/. 50.00 超过了您可预支的金额 B/. 40.00：余额的 80% 减去已申请的部分）

> **您需要了解的风险：** 下拉列表允许 **任何已登录的用户** 以 **任何员工** 的名义提交申请，而 B/. 100 及以下的申请会自动批准。建议做法：只由主管在员工口头提出后登记申请；每天检查 **待处理** 和 **已批准** 列表；没有在页面上看到申请之前不要付钱。

**批准、拒绝和标记已支付。** 角色：**批准** / **拒绝**：管理员、主管。**标记已支付**：仅限管理员。

1. 在 **预支申请** 中按 **状态** 筛选（**待处理**、**已批准**、**已拒绝**、**已支付**）。
2. 对 **待处理** 的申请：点击 **批准**（立即生效）或 **拒绝**（填写 **拒绝原因（可选）：** 后点击 **确认拒绝**）。
3. 对 **已批准** 的申请，交付现金后：点击 **标记已支付**。

**常见错误：**

- **Saldo insuficiente: disponible B/. X, solicitado B/. Y.**（余额不足：可用 B/. X，申请 B/. Y）— 自申请以来余额减少了（例如因为一次工时更正）。
- **No hay una categoría de "pago a empleado" configurada.**（没有配置“员工支付”类别）— 请在 **支出类别** 中启用一个。
- **Solo se puede aprobar una solicitud pendiente.**（只能批准待处理的申请）/ **Solo se puede rechazar una solicitud pendiente.**（只能拒绝待处理的申请）/ **Solo se puede pagar un cobro aprobado (ya pagado o no aprobado no aplica).**（只能支付已批准的预支；已支付或未批准的不适用）

**已支付** 无法撤销：所创建的支出不可更改，如果是错误，请在 **支出** 中更正（6.1）。

### 5.1 利润看板

|---|---|

下方的 **按类别的支出** 区块显示每个类别在支出总额中的占比，以及日结列表（3.2）。链接 **查看现金流**。

### 5.2 现金流

角色：管理员、主管。

1. 菜单 **主要功能 → 现金流**（或从看板点击 **查看现金流**）。标题：**运营现金流**。
2. 按 **起始**、**截止**、**类型**（**收入**、**支出**、**供应商付款**）、**门店**、**供应商**、**类别**、**状态**、**排序** 和 **搜索** 筛选。

**请务必阅读提示：** **仅统计 GestorPro 中已登记的资金运动。不包含未付款的赊购，不等于利润，也不等于银行或现金账户的真实余额。不能替代银行对账。**

**您会看到：**

- 汇总：**总流入**、**支出**、**供应商付款**、**总流出** 和 **净现金流**（含正数天数和负数天数）。
- **手工期初资金**：您可以输入期初的现金数额，以查看 **预计期末资金**。这只是模拟：不会保存，并标记为 **手工输入，未验证**。
- **每日趋势**：按日显示流入和流出的柱状图以及累计值。
- **按收款方式的收入**：现金、刷卡、Yappy 和彩票，依据各日结的现行盘点。
- **资金运动**：每笔日结、支出和付款，带有 **流入** 或 **流出**、**状态** 和 **操作人**，每次显示 25 条。**查看来源** 跳转到登记该笔记录的页面；**查看审计** 跳转到其更正记录。

**操作：** **打印 / 保存 PDF** 和 **导出 CSV**（导出全部筛选结果）。

**请注意：** **现付** 采购不会作为资金运动显示（它们不产生付款记录），但会计入看板的 **供应商付款**。因此 **净现金流** 可能与 **利润** 不一致。

### 5.3 财务审计

角色：管理员、主管。只读。

用于查看每一次对已登记资金的更正或作废：原来的金额、现在的金额、差额、原因以及操作人。在这里不能修改任何内容，也不能删除任何记录。

1. 菜单 **管理 → 财务审计**。
2. 按 **起始** / **截止**（留空 = **全部历史**）、**模块**（**支出**、**日结**、**付款**）、**操作**（**更正**、**作废**）、**用户** 和 **搜索**（原因、供应商、类别、收银员……）筛选。按钮 **刷新**；链接 **查看现金流**。

**重要：** 日期筛选依据的是 **进行更正** 的日期，而不是原始记录的日期。

**您会看到：** 卡片 **更正笔数**、**按模块**、**原金额合计**、**现行金额合计**、**净差额**（更正所扣减的金额；并非亏损）和 **用户数**。表格列出 **更正时间**、**模块**、**操作**、**业务对象**、**原金额**、**现行金额**、**差额**、**原因**、**操作人** 以及按钮 **查看详情**。

**某笔更正的详情：** 点击 **查看详情**。面板 **更正详情** 显示 **资金时间线**（**原始记录** → **冲正（抵消原始）** → **更正（正确金额）** 或 **无新金额（作废）** → **现行金额**）、**更正数据**（原因、用户、差额、标识号）以及 **记录详情**（类别；或供应商与发票，其中发票总额显示在 **期初余额** 标签下；或门店、收银员、班次以及原始盘点与现行盘点的对比，视情况而定）。

**操作：** **打印 / 保存 PDF** 和 **导出 CSV**（至少有一条记录时显示）。您也可以从任何列表点击 **查看审计** 进入此处。

## 6. 出现问题时

### 6.1 更正金额错误（支出、付款与日结）

角色：管理员、主管。

**支出**、**供应商付款**和**日结**都不可更改。出现错误时，系统会生成一笔**冲正**（自动记录，以相同金额抵消原始记录），并在需要时生成一笔**更正**（记录正确金额的新记录）。原始记录保持不变，全部过程都留在**财务审计**（5.3）中，看板、现金流和欠款的合计会自动重新计算。

您需要了解的后果：

- 每笔记录**只能更正一次**。第二次尝试会显示 **El movimiento ya fue corregido: no admite una segunda corrección.**（该笔已更正过，不允许第二次更正）（某些情况下您可能看到另一种提示 **该笔已更正过，不能再次更正。**）。更正是最终的：确认前请仔细核对金额。
- **原因**始终为必填，并会被记录下来。
- 没有“您确定吗？”的询问：确认按钮本身就是确认。

**步骤：**

1. 进入该笔记录所在的列表：**支出**（支出）、**付款历史**（付款）或**看板**（日结）。只有状态为**有效**的记录才有该按钮。
2. 点击行末的**更正**。会打开**更正记录**，显示该笔记录的说明和**已登记金额：B/. X**（B/. 为巴波亚，巴拿马货币），以及提示 **El movimiento original NO se modifica ni se borra: se anula con un reverso y, si corresponde, se registra el importe correcto. Todo queda en la auditoría. Solo se puede corregir UNA vez.**（原始记录不会被修改或删除：会用一笔冲正将其作废，并在需要时登记正确金额。全部过程都留在审计中。只能更正一次）。
3. 选择一个选项：
   - **更正金额**（“该笔确实发生，但金额不对。”）。修改**正确金额 (B/.)**（默认填入已登记金额）。对于日结，此处显示的是**更正后的现金盘点**区块，其中**现金**、**刷卡**、**Yappy** 和**彩票**已预先填入：请把**四项**都填成正确的值，因为更正后的盘点会完整替换原始盘点。
   - **作废该笔**（“本不该登记：金额归零。”）。
4. 填写**原因**（必填；字段示例：“例如：把 15 误输成 150。”）。
5. 点击**登记更正**（或红色的**作废该笔**）。对话框在服务器确认之前不会关闭。

**完成后您会看到：** **更正已登记：该笔金额已更新。**（付款时为：**更正已登记：该笔付款已更正，发票欠款已重新计算。**）。列表中状态变为**已更正**（原金额划线 + 新金额）或**已作废**（该行变淡，金额为 B/. 0.00）。**更正**按钮被替换为**查看审计**。

**示例：**您把一笔 B/. 15.00 的燃油支出登记成了 B/. 150.00。**更正** → **更正金额** → **正确金额 (B/.)** `15` → **原因**“把 15 误输成 150” → **登记更正**。列表中会显示 ~~B/. 150.00~~ B/. 15.00，状态为**已更正**，本期合计减少 B/. 135.00。财务审计中会出现一条**更正**事件，**差额**为 −B/. 135.00。

**各类型的特别说明：**

- **付款：**如果选择**更正金额**，正确的付款日期为今天；如果选择**作废**，该付款金额为零，发票欠款会重新上升（可能回到**部分付款**或**待付**）。原始付款保留原日期，冲正的日期为今天。如果更正后因网络故障列表没有刷新，**更正其实已经登记成功**：请不要重复操作。
- **日结：**如果结账确实存在但数据有误，请用**更正金额**，不要用**作废该笔**。已作废的结账**仍然占用**门店 + 日期 + 班次 + 收银员这一组合，因此之后无法再登记相同的结账。

**常见错误：**

- **请输入有效金额（0 或更大）。**
- **El motivo de la corrección es obligatorio.**（更正原因为必填）
- **El movimiento ya fue corregido: no admite una segunda corrección.**（该笔已更正过，不允许第二次更正）
- **La corrección excede el saldo de la factura: el pago efectivo superaría el total de la compra.**（更正金额超过发票余额：实际付款将超过采购总额）（仅付款；请使用较小的金额）。
- **La corrección de un cierre requiere el arqueo corregido.**（更正结账需要填写更正后的现金盘点）（仅结账）。

### 6.2 我登记的发票金额或类型有误

发票不能编辑、不能删除，也没有更正功能。请根据情况处理：

- **登记金额小于实际金额：**为同一供应商再登记一张差额发票，发票号用原号加后缀（例如 `F-3310-AJUSTE`），类型相同。欠款总额就会正确。
- **登记金额大于实际金额、发票本不该存在，或类型错误（现付误记为赊购，或相反）：**目前应用中没有受支持的方式来减少或作废发票；多出的余额会作为“幽灵”欠款留在应付账款和对账单中。**请联系服务商支持（6.6）**，提供发票号、供应商和正确金额，不要为了“结清它”而登记付款。
- **供应商在开票后给了折扣：**与上一种情况相同（登记金额大于实际金额）。在此期间，只支付实际金额，并在支持处理时于原因中注明该折扣。

### 6.3 打卡错误、忘记打下班卡与异常

**打卡记录不可更改**：无法从打卡机或任何界面删除或修改。会发生什么，以及负责人在**工时**中看到的内容：

| 情况 | 结果 | 工时显示的详情 |
|---|---|---|
| 打了**下班**卡但没有**上班**卡 | 不生成工时。 | — |
| 两次**上班**或两次**下班** | **异常**，工时为零。 | **Falta el fichaje de entrada o de salida, o está duplicado.**（缺少上班或下班打卡，或有重复） |
| 两次**外出就餐**或两次**就餐返回** | **异常**。 | **Fichajes de comida duplicados.**（就餐打卡重复） |
| **就餐返回**早于**外出就餐** | **异常**。 | **Los fichajes de comida están en desorden.**（就餐打卡顺序错乱） |
| 有**外出就餐**但没有**就餐返回**（或相反） | **异常**。 | **Fichajes de comida incompletos (falta la salida o la vuelta de comida).**（就餐打卡不完整：缺少外出或返回） |
| 下班时间早于上班时间 | **异常**。 | **La salida no es posterior a la entrada.**（下班时间不晚于上班时间） |
| 忘记打**下班**卡 | 上班打卡成为“孤立”记录；清扫之前不生成工时。 | **Fichaje de entrada sin salida (huérfano).**（只有上班没有下班的打卡（孤立）） |

**负责人该怎么做（逐步）：**

1. 如果员工忘记打**下班**卡：等到上班打卡后超过 16 小时，以**管理员**身份在**工时**中点击**清扫孤立打卡**。您会看到**已标记 {n} 条孤立打卡。**或**未发现孤立打卡。** **没有自动流程**：只有有人点击该按钮时，没有下班的上班打卡才会被标记为异常。
2. 找到状态为**异常**的工时并点击**更正**（4.10）：填写原因、实际的**工作分钟数**、**加班分钟数**和按 4.9 的表格计算出的**加班金额**，并保持勾选**解决异常（标记为已更正）**。
3. 如果错误的打卡经过了**审核队列**（3.6），请同时在那里拒绝它，以留下记录。

对员工：请当天告知您的主管；不要试图通过多打几次卡来“修复”。

### 6.4 平板无法使用：没有令牌或没有网络

- **设备未配置**：缺少打卡机令牌。管理员在**管理 → 打卡机**中获取（创建打卡机时或通过**重新生成令牌**），然后在平板上粘贴并点击**保存**（2.6）。如果重新生成令牌，旧令牌将失效。
- **Kiosco no autorizado**（打卡机未授权）：令牌无效，或选择器中选中的打卡机与这台平板不对应。请选择正确的打卡机；如果问题持续，请重新生成令牌。
- **网络错误，请重试。** / 平板没有网络：**没有离线模式**。请用纸记录每次上班和下班的时间。当天结束时，主管在**工时 → 更正**中为每位受影响的员工更正工时（工作分钟数、加班分钟数和金额，原因写“打卡机无网络”）。如果当天没有生成工时（没有人打下班卡），就没有可更正的行：这种情况下无法从界面创建工时；请联系支持（6.6）并保留纸质记录。
- **平板在班中关机**：已发送的打卡会保留；开机后重新打开 **https://app.gestorpro.us/kiosco** 并再次选择**打卡机**（除非浏览器数据被清除，否则令牌会保留）。

### 6.5 密码与会话

**随时修改您的密码。** 角色：全部。

1. 在侧边菜单底部，点击**修改密码**（钥匙图标）。
2. 填写**当前密码**、**新密码**和**确认新密码**。
3. 点击**修改密码**。这里可以**取消**或按 Escape 键关闭。
4. 您会看到**密码已更新**，然后需要点击**前往登录**并重新登录。

**重要：**修改密码后，您在所有设备上的**全部**会话都会被关闭（手机、其他标签页、平板）。事先不会提示；如果在其他标签页中有未完成的表单，将会丢失。（在**用户**中，您自己那一行的提示说密码在“顶部栏”修改；正确的位置是侧边菜单。）

**退出登录。** 点击侧边菜单底部的**退出登录**（退出图标）。不会要求确认，直接返回**登录**页面。只会退出本设备的会话；要一次性退出所有设备，请修改密码。会话有效期为**自登录起 30 天**（使用应用不会延长），即使关闭标签页或浏览器也是如此。在共用电脑上，结束后请务必退出登录。

**某位用户忘记了密码（完整流程）。** 没有“找回密码”功能。

1. 一位**管理员**进入**管理 → 用户**，在该人员所在行点击**重置密码**。会打开**重置密码 — {nombre}**，其中显示文字**设置一个临时密码。该用户的所有会话将被关闭，下次登录时必须修改。**
2. 填写**临时密码**和**确认临时密码**，然后点击**重置**。会看到**密码已重置** — **请将临时密码告知 {nombre}：下次登录时必须修改。**
3. 当面告知临时密码。
4. 该人员用临时密码登录；会出现强制的**修改密码**对话框（2.1），由其设置自己的密码。
5. 点击**前往登录**，用新密码登录。

您自己那一行显示**你的账户**（您的密码在侧边菜单修改）。如果账户已停用，该按钮不可用（**账户已停用：无法登录，重置密码不会生效。**）。如果唯一的管理员忘记了密码，需要向服务商支持申请（6.6）。

## 8. 常见问题

**1. 我登记了一张发票，但在应付账款里看不到。丢了吗？**
没有丢。很可能您把它登记为 **现付（当场付清）**。请到 **主要功能 → 全部发票**，按 **类型：现付** 筛选查找。见 3.4。

**2. 我登记错了一笔支出。怎么删除？**
不能删除。在 **支出** 中点击 **更正**，然后按 6.1 操作。只能更正一次。

**3. 为什么我不能支付超过所欠的金额？**
因为那会造成超额付款，GestorPro 一律阻止（**金额不能超过余额（B/. X）。**）。如果供应商多收了钱，请在系统之外与其解决；如果发票本身的金额错误，见 6.2。

**4. 我更正了一笔付款，又弄错了。可以再更正一次吗？**
不可以：每笔记录只允许一次更正。如果更正后的付款仍然不对，请按差额登记一笔新的付款（如果少付了），或咨询支持人员如何记录。

**5. 我用正确的密码登录，却提示“Credenciales inválidas.”。**
如果您的账户已被停用或公司已被暂停，也会出现这条提示（意为“凭据无效”）。请联系贵公司的管理员；如果您就是管理员，请联系服务商的支持人员（6.6）。

**6. 我忘记密码了。“找回密码”在哪里？**
没有这个功能。请按 6.5 的流程：由管理员在 **用户 → 重置密码** 中为您设置一个临时密码，您用它登录、修改密码，然后重新登录。

**7. 我修改了密码，手机上也被登出了。**
这是有意设计的：修改密码会关闭所有设备上的全部会话。请用新密码重新登录。

**8. 收银员已经结账，但填错了。我要重新登记结账吗？**
不需要。您会看到 **Ya existe el cierre de esa cajera y turno para la fecha; use una corrección para ajustarlo.**（该日期、该收银员和班次的结账已存在；请用更正来调整）。在看板中点击该行的 **更正**，选择 **更正金额**，然后填写完整、正确的现金盘点。不要作废它：作废的结账仍会占用该班次。

**9. 为什么“采购登记”比“供应商付款”大得多？**
因为您是赊购。差额就是您的欠款，可在 **应付账款** 中查看。**利润** 只计算已付的部分（5.1）。

**10. 看板的“利润”和“净现金流”对不上。**
两者是不同的计算：现金流不把现付采购算作资金运动；而看板会把它减掉。这两个数都不是您的银行余额（5.2）。

**11. 一张发票显示“逾期”，但在账龄里却是“0–30 天”。哪个是对的？**
两个都对。**逾期** 是相对于到期日而言；**账龄** 则是从开票日期起计算的天数（4.4）。

**12. 我怎么给会计导出报表？**
在 **现金流**（该期间的全部资金运动）、**应付账龄**、**对账单** 和 **财务审计** 中使用 **导出 CSV**；这些文件可以用 Excel 打开。支出和付款历史请在界面上按期间查询。

**13. 我怎么查看这个月各门店的销售额？**
**看板** → 选择该月的 **起始** / **截止** → **门店**。**销售** 卡片就是各次结账的总和。

**14. 我怎么登记半月工资或月薪的发放？**
作为支出登记（3.3），选择员工支付类别，并选 **支付类型：半月** 或 **每月**；需要该员工的技术标识。如果没有，请使用一个没有员工标记的 "Planilla"（工资表）类别，并把姓名写在 **描述** 中。另见 4.11。

**15. 不属于加班的借款或工资预支记在哪里？**
作为支出登记，选 **支付类型：预支**（或 **其他**）。菜单中的 **预支** 只用于加班预支。

**16. 我怎么登记店铺租金？**
作为支出登记，类别选 **Alquiler**（租金，系统预置的类别），并选择对应的门店。

**17. 可以登记昨天的支出吗？昨天的付款呢？**
支出：可以，修改 **业务日期** 即可。付款：**不能**，始终记为今天的日期；因此最好在实际付款的当天登记。

**18. 付款计划器已经把发票付了吗？**
没有。它只是一份建议，不会保存任何内容。请在 **应付账款 → 付款** 中逐笔登记付款，并在离开该页面前打印或导出计划。

**19. 一名员工打了两次“上班”卡。怎么删除重复的打卡？**
不能删除。该工时会显示为 **异常**；请在 **工时** 中更正（6.3）。

**20. 一名员工忘了打下班卡。怎么办？**
等待超过 16 小时后，点击 **清扫孤立打卡**（仅管理员可用），然后更正工时（6.3）。没有自动处理流程。

**21. 我在审核队列中拒绝了一条打卡，但工时没有变化。**
这是正常的：拒绝只是记录您的决定。还需在 **工时** 中更正该工时（4.10）。

**22. 可以修改加班费的加成比例吗？**
不可以。加成比例（白班 25%、夜班 50%、混合 75%、节假日 150%）是巴拿马法律规定的最低标准，不可配置。

**23. “预支”是用来向客户收款的吗？**
不是。GestorPro 不管理客户。**预支** 是给员工的加班预支（4.12）。销售额在看板中以结账的方式登记。

**24. 员工（角色）和员工（档案）有什么区别？**
**员工角色** 是一个可以登录 GestorPro、以只读方式查看所有内容的用户账户。**员工档案** 是在打卡机上打卡的工作人员；不需要账户。见 1.5 和 2.5。

**25. 有账户的员工能看到资金数据吗？**
能：员工角色可以查看看板、支出、付款、供应商和欠款。只为确实需要查看的人创建这类账户（1.5）。

**26. 我怎么修改员工的姓名（例如结婚后改名）？**
**员工 → 编辑 → 保存更改**。以前的结账记录会保留登记时使用的姓名。

**27. 我想停用一个类别，但被阻止了。**
您会看到 **Debe quedar al menos una categoría de "pago a empleado" activa…**（必须至少保留一个启用的“员工支付”类别）。请先创建或重新启用另一个员工支付类别，再停用该类别（2.3）。

**28. 员工在打卡机上刷二维码卡，提示“Empleado no encontrado o inactivo.”。**
目前打卡机只识别 **工号**（例如 E001）；二维码读取功能尚未开放。该提示意为“未找到员工或员工已停用”。请输入工号，并在 **员工** 中确认该员工处于 **启用** 状态。

**29. 打卡机没有网络，员工无法打卡。**
没有离线模式。请用纸记录时间，由主管在当天结束时更正工时（6.4）。

**30. 平板显示“设备未配置”。**
缺少打卡机令牌（2.6 和 6.4）。

**31. 在手机上看不到公司名称，也不能切换语言。**
在窄屏幕上这些控件会被隐藏。请在登录界面切换语言，或使用更宽的屏幕（见 7）。

**32. 我看到了英文内容。**
有两种正常情况：**Rate limit exceeded, retry in 1 minute**（登录尝试次数过多；请等待一分钟）以及输入不存在的网址时出现的无菜单错误页（点击“返回”或输入 **https://app.gestorpro.us**）。其他任何英文内容，请截图报告给支持人员。

## 9. 术语表

- **付款（Abono）**：对赊购采购发票的部分或全额付款。在 **应付账款 → 付款** 中登记。
- **异常（Anomalía）**：因打卡缺失、重复或顺序错乱，系统无法计算的工时记录。在 **工时** 中更正。
- **账龄（Antigüedad）**：有未结余额的赊购发票自开票日期起已过的天数。与"逾期"不是同一个概念。
- **作废（Anular）**：通过冲正把一笔资金记录归零，但不删除。这是 **更正记录** 的两个选项之一。
- **现金盘点（Arqueo）**：交班时清点钱箱中的款项，按现金、刷卡、Yappy 和彩票分项。
- **财务审计（Auditoría financiera）**：所有资金更正和作废的永久记录。只能查看，永不删除。
- **B/.**：巴波亚（balboa），巴拿马货币；1 巴波亚 = 1 美元。
- **Cajera / Verificador**（收银员 / 核验员）：员工的操作角色（在门店中的职能）。不是系统角色。
- **现金结账（日结）**：收银员一个班次的销售总额记录，依据现金盘点和 Firestec。
- **加班预支（Cobro anticipado de horas extra）**：在发放半月薪之前，预先支取员工加班余额的一部分。
- **现付（Contado）**：收到发票时即已付款的发票。不产生欠款。
- **更正（Corrección）**：更正一笔记录时，与冲正一起生成的、带有正确金额的新记录。
- **赊购（Crédito）**：有付款期限的发票。会产生欠款，并显示在应付账款中。
- **员工（Empleado）**：在打卡机上打卡的工作人员档案。不是登录账户。
- **对账单（Estado de cuenta）**：与某个供应商在某一期间内的对账文件。
- **打卡（Fichaje）**：在打卡机上记录的上班、外出就餐、就餐返回或下班。永久保存。
- **例外打卡（Fichaje de excepción）**：因验证失败而通过 PIN 或主管授权完成的打卡。会进入 **审核队列**。
- **Firestec**：外部销售点系统。GestorPro 只接收结账总额。
- **现金流（Flujo de caja）**：按登记内容列出的资金流入和流出。不是利润，也不是银行余额。
- **夜间时段（Franja nocturna）**：18:00 至 06:00；用于判定一条工时是白班、夜班还是混合。
- **孤立打卡（Huérfano）**：上班打卡后超过 16 小时仍无下班打卡；用 **清扫孤立打卡** 标记。
- **不可变（Inmutable）**：不能编辑也不能删除。适用于支出、付款、发票、结账、打卡和更正。
- **工时（Jornada）**：根据员工的打卡记录，按日计算的工作时数和加班时数。
- **打卡机（Kiosco）**：员工打卡用的平板或电脑。需要令牌。
- **彩票（Lotería）**：从钱箱中付给顾客的彩票奖金；中奖彩票计入结账总额。
- **成员（Membresía）**：一个用户账户对某家具体公司的访问权限（一个账户可以属于多家公司）。
- **异常模式（Modo de excepción）**：门店的设置，决定验证失败时员工是用 PIN 打卡、由主管授权打卡，还是两者皆可。
- **现行金额（Monto vigente）**：一笔记录经过更正后的当前金额（更正后的金额；若已作废则为零）。
- **冲正（Reverso）**：自动生成的记录，以相同金额抵消原始记录，原始记录保持不变且仍可见。
- **系统角色（Rol del sistema）**：用户账户的权限：管理员、主管或员工。
- **RUC / NIT**：供应商的税务登记号。
- **加班余额（Saldo de horas extra）**：加班累计的金额减去已批准的预支；是 **预支** 中预支的依据。发放半月薪时不会清零。
- **门店（Sede）**：企业的每一个营业场所或分店。
- **超额付款（Sobrepago）**：付款超过发票余额。GestorPro 始终禁止。
- **打卡机令牌（Token del kiosco）**：授权某台平板发送打卡记录的秘密密钥。只显示一次，并保存在该平板的浏览器中。
- **用户（Usuario）**：使用邮箱和密码登录 GestorPro 的账户。
- **有效 / 已更正 / 已作废**：一笔资金记录的状态，取决于它是否被更正过。
- **Yappy**：在收银处收到的手机转账付款（Banco General）。

## 附录 B：仅供 GestorPro 服务商使用（平台管理）

本节仅供服务商内部使用。客户日常操作不需要本节内容。

系统中有一个特殊的**平台**账户（超级管理员），它**不进入任何公司**：只能看到**平台**页面（标题为**创建公司**，副标题为**新增一个客户（公司）及其首位管理员。**）。在该页面可以：

- **创建公司**：填写名称、**标识符（slug）**（用于网址的短名称：仅限小写字母、数字和连字符）、管理员的姓名和邮箱，以及**初始密码**（临时密码）。创建时会默认生成支出类别 **Servicios públicos**（公共事业费）、**Alquiler**（租金）、**Mantenimiento**（维护）和 **Pago a empleado**（员工支付；最后一项标记为「员工支付」类别），操作角色 **Cajera**（收银员）和 **Verificador**（核验员），以及收款配置（80 % 可收取，审批阈值 B/. 100）。
- **公司**表格，含**状态**（**启用** / **已暂停** / **已取消**）和操作：**暂停**、**重新启用**、**取消公司**（需再点击一次确认：**确认暂停？** / **确认永久取消？**）、**添加成员**（让已存在于其他公司的用户获得本公司的访问权限；该对话框只提供**员工**和**管理员**两个角色）以及**重置 admin 密码**（生成一个**仅显示一次**的临时密码，并带有**复制**按钮）。只有公司处于**启用**状态时，**添加成员**和**重置 admin 密码**才可用。

对客户的影响：当一家公司被**暂停**时，其所有用户会立即被强制退出且不会收到任何提示；再次尝试登录时，即使密码正确，也会看到 **Credenciales inválidas.**（凭据无效）。**重新启用**会恢复访问权限，不会更改密码。**取消**是永久性的。公司永远不会被删除。

如果客户反映"我无法登录，但密码是正确的"，首先应检查其公司的状态。

## 附录 C：过时的界面文字（供技术团队参考）

以下内容是在将本手册与应用程序对照时发现的；本手册描述的是实际行为。
